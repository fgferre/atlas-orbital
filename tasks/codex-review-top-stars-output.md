## Context

We just shipped a correction (commits `f8d8bff` + `8668b20`) replacing
a Stefan-Boltzmann physical-radius port with Gaia Sky's
source-authoritative **pseudo-size** derived from absolute magnitude:

pseudoL = 10^(-0.4 · absMag)
size = sqrt(pseudoL) × 0.15 (parsecs)

Pipeline (`src/components/canvas/Starfield.tsx` + `src/lib/starPhysics.ts`):

1. HYG binary → apparent mag + distance → absolute mag
2. absMag → pseudoSize (pc) via `absoluteMagnitudeToPseudoSize`
3. a_size (scene units) = pseudoSize × DISTANCE_SCALE × STAR_SIZE_FACTOR
4. shader: solidAngle = a_size / dist
5. opacity = lint_smoothstep(solidAngle, u_solidAngleMap, u_opacityLimits)
6. solidAngle = clamp(pow via degrees12/radians12 wrap, u_minQuadSolidAngle, 3e-8)
7. gl_PointSize = solidAngle × u_sizeFactor × pixelsPerRadian
8. fragment: alpha = opacity × u_alphaFactor × boundaryFade; color from bvToRGB × vfxHdrGain

User reports visually "Capella looks larger than Sirius". Our math
says otherwise — Sirius clamps at 3e-8 → 50.5 px, Capella at 31.7 px

### Part 2: Pipeline bugs that could invert the visual ordering

Independently of the math table, audit `src/components/canvas/Starfield.tsx`
for any shader / material / post-process effect that could make
Capella (mag 0.1, warm yellow/orange) APPEAR larger than Sirius
(mag -1.4, cool blue-white) on-screen despite Sirius having ~60%
more pixels. Specifically check:

a. **GL_POINTS size cap.** `gl_PointSize` may be clamped by the
driver. Is there a `GL_POINT_SIZE_MAX` constant set or queried?
On most drivers 64-256 px is typical. If Sirius (50.5 px) is
BELOW the cap but a larger star saturates at the cap, no issue —
but worth flagging.

b. **Bloom / selective-HDR interaction.** The fragment outputs
premultiplied rgb = (vColor + core*2) * alpha. `vColor = bvToRGB(ci)
    × vfxHdrGain`. If `bvToRGB` returns vec3(1,1,1) for Capella and
vec3(0.5, 0.7, 1) for Sirius (hypothetical), then Capella's LUMA
could be higher despite the same sprite area — tripping the
Bloom `luminanceThreshold = 1.0` harder. Check `bvToRGB` at
`Starfield.tsx:127-138` and the Bloom integration. Does the
3-branch piecewise output luma > 1 for any input, so Capella
could bloom more than Sirius?

c. **Fragment premultiplication + blending.** Commit history says
blending is OneFactor/OneFactor additive; fragment premultiplies
by alpha. Any math error here that would amplify the wrong star?

d. **Proper motion drift.** `velocity * yearsSinceJ2000` — if
`yearsSinceJ2000` runs large, any star that has huge proper
motion could drift off-screen or close to camera in ways that
change solidAngle. Mostly a non-issue at J2000 ±10 years but
check the range.

e. **Fragment halo texture sampling.** `profile = texture(u_starTex, uv).r`
— the baked gaussian halo amplifies the perceived size beyond
`gl_PointSize`. If the halo tex is different for stars of
different color/bv, flag it. (It shouldn't be — single texture
shared across all stars.)
